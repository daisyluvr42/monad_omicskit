# 分析前的数据整理与校验

由模型识别材料含义、选择字段，并调用宿主文件工具或本地 Python/R 读取和保存数据；大表使用脚本提取，不在对话中逐行重抄。此步骤由 Skill 指导宿主完成，不是 `monadomics` 新增的导入命令，也不预设某厂商的固定目录结构。

## 读取原材料

- 保留原文件；压缩包解到任务目录，找到完整定量表、样本对应表、差异结果及相关报告。报告用于理解字段、方法和设计，完整表用于提取数值。只有报告时，先判断其中是否包含所需完整数据；不能从图片或节选补造遗漏行。
- 依据实际内容区分 Excel 工作簿和分隔文本；`.xls` 可能是制表符文本。读取相关工作表及表头说明，辨认基因/转录本 ID、样本、注释和数值列。缺少读取能力时准备必要工具或明确指出限制，不能声称已完成提取。
- 从原报告或表头确认物种、参考版本、定量方式、是否取对数、分组与比较方向。不能仅凭文件名、列名猜测或数值为整数就确定数据含义。蛋白、代谢物及单细胞数据先核对现有分析范围，不因外观像矩阵就按普通转录组处理。

## 清洗前补齐必要信息

先对照已有对话、报告和样本说明，只询问当前任务尚缺且会改变方法或结论的信息，不要求每次补齐一套字段：

- 研究目标、比较哪些组及谁作为对照，由用户请求或已有方案确定；不因文件中恰好有两组就自行决定研究目的。
- 物种、表达量类型、对数尺度及 ID 类型优先查材料。物种相关注释或富集需明确物种；仅盘点文件不必因此停下。可疑的 ID 格式或数值分布只是线索，不能代替来源确认。
- 需要确定分析设计时，查明样本是否来自同一个体、是否重复测量，以及分组与实验批次的关系。材料没有记录，不等于不存在配对或批次。

集中列出已确认内容和本次需要补充的问题，用研究者熟悉的实验语言提问，并简述其用途。例如：“已找到 A、B 两组各 4 个样本，但未找到物种、比较目的和配对说明。请补充物种、希望比较的处理或状态及对照组，以及两组是否来自同一批个体，以确定注释和比较设计。”问题按实际缺口删减，不让用户重复解释已有信息或填写设计公式。

用户暂时无法提供时记为未知，不默认“无批次”或擅自选择对照；暂停依赖该信息的处理和分析，继续不受影响的工作。配色、排版等可采用合理默认值的偏好不阻塞分析。将确认信息及其文件出处或用户说明记入现有 `input-check.md`；后续直接复用，出现新冲突或任务改变才补问，不另建问卷或审批表。

## 规范表格

按本次分析创建所需表格即可，不强制凑齐整套文件。使用 UTF-8 CSV 或 TSV，单行表头，无合并单元格；ID 保留为字符串，数值保持原精度。文件名可按项目命名。

| 表格 | 字段与含义 |
| --- | --- |
| 表达矩阵，例如 `counts.tsv`、`fpkm.tsv` | 首列 `gene` 为原基因 ID，其余每列对应一个实际样本，行是基因。counts、TPM、FPKM 分文件，不夹带注释列、组均值或统计指标。 |
| 样本表，例如 `samples.tsv` | 首列 `sample` 与矩阵列名对应，`group` 为原材料确认的分组；按需要保留 `batch`、配对编号等已有变量。 |
| 差异结果，例如 `deg.tsv` | `gene`、`log2FoldChange`、`pvalue`、`padj` 按原表实际可用字段提供；说明比较方向、方法及校正方式，保留原列到规范列的对应。没有的统计值不得补填。 |
| 排序或候选基因表，例如 `ranked.tsv`、`genes.tsv` | GSEA 使用完整的 `gene` 与有方向的数值 `score`，记录指标定义；ORA 候选表用 `gene`，适用时另存实际背景基因。仅有显著基因名单时不能生成完整排序。 |
| 生存表，例如 `survival.tsv` | 首列 `sample`，随后为时间、0/1 事件及所需预测变量；记录时间单位与事件编码定义。字段通过实际命令参数指定。 |

原基因注释需要保留时另存注释表。基因 ID 与 symbol 不能视为可互换；转录本不能仅按同名基因直接合并。ID 重复、缺失、映射不唯一时先说明并依据分析需要解决，防止后端自动合并造成未记录的数据变化。

格式整理仅允许有来源的选列、改表头、转置及样本顺序对齐等操作。不要在这里擅自删样本/基因、取整、填零、插补、log 转换、z-score、批次校正或重算显著性。FC 不等于 log2FC；FDR/q-value 的定义也要核实。确实需要尺度或统计转换时，在后续分析中明确记录方法，保留原数值。

## 保存后与原材料复核

1. **重新打开已保存表格和原始数据文件**，先结合行名、表头及说明确认字段语义，再按照原始 ID 与明确的列映射全量核对。矩阵与样本元数据都要比较，不能只比对同一个中间对象，不能仅抽几行就宣布全表一致。表头比数据行少一列时先判断是否为行名，而非直接认定原表损坏。来源为 PDF/图片时还需对照原页确认识别结果；无法完成核对就说明尚未通过。
2. 核对原表范围内的行数、样本集合和对应关系，检查重复 ID、缺失值以及是否误用了报告预览、组均值、转录本表或显著子集。有意选取的范围需写明，不以截取行数冒充全量。
3. 与原报告、表头说明及样本信息核对样本数、分组、比较方向、物种、表达单位、对数尺度和统计字段定义。报告缺失时可依据原表和用户提供的说明核验，但不能声称核对过报告。材料有冲突时保留冲突并查清，不默默选一方。
4. 在任务目录的 `input-check.md` 简记：原文件/工作表与所用范围、规范文件及列映射、实际行列数、数据类型与分组方向、执行的校验和结果、尚未解决的问题。已确认的必要信息和数值一致后继续；缺失且影响方法或结论的信息先询问，未通过的表格不用于分析。

保留的提取脚本必须包含最终修复；新建或修改后在独立输出目录执行，对照当前核验过的矩阵及样本表。脚本应允许指定输出目录，避免复跑覆盖正确输入。未改变的输入不重复转换，复核记录不要求额外审批表。

后续调用遵守 @references/commands.md。例如差异分析引用矩阵和样本表；富集需要数组或对象参数时从已核验表中读取，不能另行生成一份未经核验的基因名单。
